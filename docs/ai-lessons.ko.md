# AI 활용에 대한 반성

이 문서는 이 저장소를 만들며 AI를 쓰다가 생긴 잘못을 한곳에 모은 것입니다. 잘못된 방향, 측정 실수, 문서 오류를 모두 담았습니다. 측정 코드와 문서는 대부분 AI 코딩 도구(Claude, Codex)가 썼고, 다른 AI가 검토했습니다. 어떤 도구가 쓰고 검토했든, 저장소 내용의 책임은 모두 저에게 있습니다.

표의 "AI 활용과의 관계"는 기록에서 확인되는 만큼만 적었습니다. 기록에 없으면 "불명확"이라고 썼습니다. 제가 직접 정한 실험 조건은 AI 탓으로 돌리지 않았습니다. 발견자 칸의 "AI 검토"는 비공개 검토 메모(공개 저장소에는 없음)를 가리킵니다. 날짜는 2026년의 커밋 날짜입니다.

## 되풀이된 패턴

**1. AI가 쓴 측정·검사 코드를 독립 확인 없이 믿었습니다.** 코드가 돌아가고 숫자가 그럴듯하면 맞다고 보았습니다. 물리적으로 가능한 값인지 같은 확인은 외부 검토가 해 주었습니다. 해당: 1, 2, 3, 5, 6, 14, 28.

**2. 해석이 데이터보다 먼저 결론이 되었습니다.** 원인 설명이 그럴듯해서 문서에 먼저 적었고, 나중에 데이터가 뒤집었습니다. mmap 가설은 반증했다가 다시 확인했고, "절벽"은 네 판본 동안 커널 현상으로 읽었습니다. 해당: 2, 6, 9, 10, 13.

**3. 숫자가 단일 출처 없이 판본 사이에 복사되었습니다.** 같은 문장 안에서 다른 판본, 다른 대표값, 다른 계산식의 숫자가 섞였습니다. 해당: 11, 15, 17, 20, 21, 22, 25.

**4. 문서의 표현이 근거보다 강했습니다.** "견고", "근사가 아니다", "같은 4비트", 출처 없는 인용이 그대로 남았습니다. 철회한 방식의 값을 근거로 쓴 문장도 있었습니다. 해당: 13, 18, 19, 23, 24, 26.

**5. 한 곳의 검사나 출력을 그대로 믿었고, 같은 종류의 실수가 새 곳에서 다시 나왔습니다.** "고쳤다"는 상태를 확인 없이 믿었더니 prefill 혼입이 다른 모습으로 돌아왔습니다(5). 대표값 고르기의 편향을 지적한 문서가 값이 가장 작은 입력만 대표 숫자로 실었습니다(11). 검사 스크립트(28)도 같은 문제였습니다. 해당: 5, 11, 28.

**6. AI와 직접 관련이 없거나 기록상 불명확한 경우입니다.** 엔진과 양자화를 섞은 처음 설계, 잠자기, 몰아서 반복한 순서, 선행 연구를 늦게 확인한 일이 여기에 듭니다. 차례로 잰 메모리 조건(27)은 제 선택이었습니다. 해당: 4, 7, 8, 16, 27.

**7. AI가 한 작업의 부작용을 바로 확인하지 않았습니다.** 기록을 다시 쓴 뒤 README의 커밋 링크가 깨졌고, push한 뒤에야 고쳤습니다. 해당: 29.

## 지금 하는 방식 (바꾼 점)

**이미 하고 있는 것 (저장소에 있음)**

- `tools/audit.py`: 분석 전에 잠자기, 불완전한 셀, 타이밍 불일치를 점검하는 무결성 게이트입니다. 반복 간 흔들림 검사도 있습니다.
- 행마다 `started_at`, `ended_at`, `swap_used_gb`, `ballast_gb`를 기록하고, 측정은 `caffeinate -i`로 실행합니다.
- 측정 순서를 전체에서 섞습니다.
- 측정 코드는 이제 토큰별 시간 원본(`step_ms`)도 저장합니다. 현재 v7 데이터(200행)에는 없습니다.
- 진단 실험 로그를 `results/probe_*.log`로 보관합니다.
- `tools/claims.py --check`: README와 상세 설명의 핵심 문장·표 행 32곳을 각자 말하는 값과 대조합니다. 한계도 있습니다. 핵심 문장이 아닌 곳에서 맞는 숫자가 엉뚱한 문장에 들어가면 잡지 못합니다. 상세 보고서와 `measurement-history.ko.md`는 검사 대상이 아닙니다.
- 문서의 숫자는 `python tools/claims.py` 출력에서만 가져옵니다.
- 코드를 쓴 도구와 다른 AI에게 독립 검토를 받습니다(검토 메모는 비공개).
- 철회와 정정은 [측정 기록](measurement-history.ko.md)에 남깁니다.
- 한계는 README에 적습니다. 배경 프로그램, 차례로 측정한 순서, 기록하지 않은 환경 정보가 들어 있습니다.

**다음에 할 것 (계획, 아직 저장소에 없음)**

- 측정마다 배경 부하와 남은 메모리를 기록합니다.
- 24GB와 16GB 조건을 번갈아 측정합니다(interleave).
- 결과를 보기 전에 통과·실패 기준을 먼저 정합니다.
